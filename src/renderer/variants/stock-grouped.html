Stock sheet — organizing the SKUs

Three ways to organize the sheet, drawn with the real s26 search from today (18 SKUs · 512 units). Every SKU already follows one scheme — MODEL‑STORAGE‑COLOR with an optional variant (FE / PLUS / ULTRA) and condition prefix (OPEN‑BOX‑ / USED‑ / SCRAP‑) — so the app can group and order them by itself; nothing needs renaming in Linnworks.

How it gets built (any of the three)

  • A small parser reads each SKU once: strip a condition prefix (OPEN-BOX- / USED- / SCRAP-), take everything before the first storage token (256GB / 512GB / 1TB) as the model, the storage as a number, the rest as the color. Anything that doesn't fit the scheme lands in an Other band at the bottom instead of being hidden.
  • Grouping is render-only in the Stock tab — nothing changes in Linnworks, and the condition chips (New / Open Box / Used / Scrap), WFS view, search, and the hover tray all keep working inside bands.
  • Inline edits (stock corrections, Min, Cost), the clock history, and Export keep working row by row exactly as now; Export gains the same ordering so the purchasing sheet reads in model blocks too.
